## 2. 📅 ایده ۱ — تقویم اشغال بازار (Occupancy Heatmap)

### هدف
پاسخ به این سؤال: «کی بازار خالی است و کی شلوغ؟» → مبنای قیمت‌گذاری تقویم کلبه خود کاربر برای سال بعد.

### داده منبع (موجود و تأییدشده)
```
GET https://api.jajiga.com/api/nights?room_id={id}
```
- بدون auth، مستقیم با curl کار می‌کند
- همیشه کل تقویم برمی‌گردد (~۸۵–۱۱۵ شب: دیروز + امروز + ۳–۴ ماه آینده)
- پارامترهای from/to/month تأثیری ندارند

### فیلدهای هر شب (night)
| فیلد | معنی |
|---|---|
| `date` | تاریخ ISO |
| `price` | قیمت واقعی آن شب (تومان) |
| `discount` | درصد تخفیف (اختیاری) |
| `is_instant` | رزرو فوری |
| `is_weekend` | آخر هفته (پنجشنبه/جمعه) |
| `is_holiday` | تعطیل رسمی |
| `is_peak` | پیک / فصل شلوغ |
| `is_unavailable` | غیرقابل رزرو (پر یا بسته) |

### قانون طلایی طبقه‌بندی هر شب (از RND-calendar.md)
```python
if n['date'] < today:
    status = 'گذشته'            # ← اول این را چک کن (دیروز هم در API می‌آید!)
elif n.get('is_unavailable'):
    status = 'پر'               # رزرو شده یا بسته توسط میزبان
else:
    status = 'خالی'
```
⚠️ دیروز ممکن است `is_unavailable: true` باشد ولی **گذشته** است نه پر.

### سطوح نمایش
- **کل بازار:** ۳۵ اتاق رادار + کلبه خود کاربر (3297585)
- **به تفکیک روستا:** سیدکلا، شیردارکلا، گونه کلا، قرآن تالار (و امیرکلا/کاردرکلا در صورت وجود در رادار)

### خروجی پیشنهادی
1. **گرید هیت مپ ماهانه شمسی:** هر خانه = یک روز، رنگ = درصد اشغال آن روز در بازار (مثلاً قرمز = ۵۰٪+ کلبه‌ها پر)
2. **نمودار خلاصه ماهانه:** درصد اشغال هر ماه به تفکیک روستا («مرداد: ۶۰٪»، «شهریور: ۴۵٪»، ...)
3. **شاخص‌های هر اتاق:** نرخ اشغال آینده، بلوک‌های رزرو (۱–۳ شب = آخر هفته، ۷+ شب = رزرو طولانی/بسته)، نیمه‌پر/چرخش

### کاربرد
- تشخیص شب‌های پیک و شب‌های خلوت بازار → چیدمان تقویم قیمت خود کاربر
- مقایسه روستاها: کدام روستا تقاضای بیشتری دارد

## 3. 💰 ایده ۲ — هیت مپ قیمت هر شب

### هدف
پاسخ به این سؤال: «آخر هفته‌ها و تعطیلات، بازار چقدر گران‌تر می‌شود؟» → مبنای تعیین قیمت شبانه خود کاربر.

### داده منبع
همان `/api/nights` — فیلد `price` در هر night، **قیمت واقعی آن شب** (نه فقط نرخ پایه «نرخ هر شب از»).

### شاخص‌های پیشنهادی (آمار توصیفی، نه مدل)
- میانه و میانگین قیمت بازار به تفکیک: روز عادی / آخر هفته / تعطیل / پیک
- **Markup آخر هفته:** (قیمت پنجشنبه/جمعه − قیمت وسط هفته) ÷ قیمت وسط هفته
- **Markup تعطیلات و پیک:** همین فرمول برای is_holiday / is_peak
- درصد کلبه‌هایی که آخر هفته گران‌تر می‌فروشند vs قیمت ثابت vs قیمت پویا

### خروجی پیشنهادی
1. **هیت مپ قیمت:** گرید روزانه، رنگ = قیمت (سبز ارزان → قرمز گران) — کل بازار به تفکیک روستا
2. جدول «چند درصد رقبا آخر هفته گران‌تر می‌فروشند»
3. شناسایی کلبه‌های قیمت ثابت vs قیمت پویا (از تاریخچه قیمت هر شب)

### کاربرد
- معلوم می‌شود بازار برای آخر هفته/تعطیل چند درصد بالاتر می‌رود — رفرنس مستقیم برای تقویم قیمت خود کاربر
- تشخیص رقبایی که قیمت پویا دارند (جدی‌ترین رقبا در قیمت‌گذاری)

## 4. 📦 وضعیت داده‌ها (چه داریم، چه کم داریم)

### داریم
| منبع | جزئیات |
|---|---|
| `data/snapshots/` | اسنپ‌شات روزانه عرضه (از 1 آگوست 2026) |
| رادار (۳۵ اتاق) | `scripts/fetch_revenue.py` — فچ nights برای محاسبه درآمد، ولی **فقط aggregated ذخیره می‌شود** |
| `fetch_occupancy.py` | اسکریپت موجود برای تقویم |
| دیتاست pricing (۱۰۸ کلبه) | نرخ پایه «نرخ هر شب از» — نه قیمت شبانه |
| `jajiga.db` | دیتابیس یکپارچه (فاز ۴ هنوز کامل نشده) |
| `docs/RND-calendar.md` | مستندسازی کامل API nights + قانون طلایی + شاخص‌ها |

### کم داریم (نیاز به جمع‌آوری)
- **تاریخچه منظم تقویم کامل هر اتاق** — تمام nights (قیمت + وضعیت هر شب) به صورت روزانه ذخیره‌شده در طول زمان.
- پیشنهاد: `scripts/fetch_nightly_calendars.py` → ذخیره raw JSON در `data/calendars/{room_id}_{YYYY-MM-DD}.json` (یا مستقیم در SQLite) + cron روزانه مانند `supply_snapshot.py`.
- هزینه: ~۳۵ درخواست در روز برای رادار — سبک است.

## 5. ❓ سؤالات باز (برای بررسی کامل بعدی)

1. اسنپ‌شات‌های فعلی (`data/snapshots/`) آیا فیلدهای price/unavailable هر شب را دارند یا فقط خلاصه؟ (اگر دارند، تاریخچه از 1 آگوست موجود است)
2. نگاشت `is_holiday`/`is_peak` سایت به تقویم شمسی — اعتبار سنجی با تقویم 1405.
3. اتاق‌های چندواحدی (`units_count > 1`) رفتار نامشخصی دارند — از محاسبه حذف شوند یا جدا؟
4. فقط ۳۵ اتاق رادار فچ شود یا ۱۰۸ کلبه pricing هم؟ (هزینه درخواست روزانه)
5. نمایش تاریخ شمسی: تبدیل ISO → Jalali با الگوریتم موجود در دشبوردها (jalaliFromIndex و ...).
6. تفکیک «رزرو واقعی» vs «بسته توسط میزبان» (بلوک بلند + قیمت پایین = بسته) — برای شاخص اشغال واقعی بهتر است بلوک‌های کوتاه آخر هفته حساب شوند؟
