## 1. 🎯 کشف بزرگ: API تقویم (بدون مرورگر!)

```
GET https://api.jajiga.com/api/nights?room_id={id}
```

**بدون auth، مستقیم از curl کار میکند!** این API بود که صفحه روم در مرورگر صدا میزد.

**پارامترهای تستشده (همه بیتأثیر هستند — همیشه کل تقویم برمیگردد):**
- `from`, `to`, `month`, `nights`, `checkin` → همگی نادیده گرفته میشوند

**پاسخ:**
```json
{
  "room": {
    "id": 3297585,
    "units_count": 1,
    "stays_min": 1,
    "stays_max": null,
    "permission_change_instant": true,
    "today_discount": 0,
    "tomorrow_discount": 10,
    "permissions": {
      "change_instant": true,
      "period_discount": true,
      "firstbook_discount": true,
      "last_moment_discount": true
    }
  },
  "nights": [
    {
      "date": "2026-07-30",
      "price": 3600000,
      "discount": 20,
      "is_instant": true,
      "is_weekend": true,
      "is_unavailable": true
    },
    {"date": "2026-07-31", "price": 2750000, "discount": 20, "is_instant": true},
    {"date": "2026-08-03", "price": 3900000, "is_instant": true},
    {"date": "2026-08-04", "price": 3900000, "is_instant": true, "is_holiday": true},
    {"date": "2026-08-12", "price": 5000000, "is_instant": true, "is_holiday": true, "is_peak": true, "is_weekend": true}
  ]
}
```

## 2. 🔑 فیلدهای هر شب (night)

| فیلد | معنی | نمونه |
|---|---|---|
| `date` | تاریخ (ISO) | `2026-08-12` |
| `price` | قیمت آن شب (تومان) | `5000000` |
| `discount` | درصد تخفیف (اختیاری) | `20` |
| `is_instant` | رزرو فوری (اختیاری) | `true` |
| `is_weekend` | آخر هفته (پنجشنبه/جمعه) | `true` |
| `is_holiday` | تعطیل رسمی | `true` |
| `is_peak` | پیک/فصل شلوغ | `true` |
| `is_unavailable` | **غیرقابل رزرو** (پر/بسته) | `true` |

## 3. 🗓️ حالتهای روز — طبقهبندی کامل

### 3.1 روزهای گذشته (beforeToday) — ⚠️ هرگز با «پر» اشتباه نشود!
- **در DOM:** کلاس `beforeToday` یا `beforeToday--holiday` یا `beforeToday--disable-middle` — **غیرفعال** (disabled)
- **در API:** ⚠️ **دیروز هم برمیگردد!** (API از دیروز شروع میشود، نه امروز)
  ```json
  {"date": "2026-07-30", "price": 3600000, "is_unavailable": true}  // دیروز! پر نیست، گذشته است
  ```
  حتی اگر `is_unavailable: true` داشته باشد — **این یعنی گذشته، نه پر!**
- **قانون طلایی:** همیشه اول چک کن `date < today` → **گذشته** (بیتوجه به is_unavailable)
  ```python
  from datetime import date
  today = date.today().isoformat()
  for n in nights:
      if n['date'] < today:
          status = 'گذشته'          # ← اول این
      elif n.get('is_unavailable'):
          status = 'پر'
      else:
          status = 'خالی'
  ```
- ❌ **اشتباه رایج:** شمردن `is_unavailable` دیروز بهعنوان «پر» → آمار اشغال غلط
- ✅ **تأیید شده با داده واقعی (31 جولای 2026):** هر ۳ اتاق بررسیشده (3297585, 3245625, 3149749) دیروز (2026-07-30) را در پاسخ داشتند — یکی با `is_unavailable: true` که **گذشته بود نه پر**

### 3.2 روز امروز (today)
- در DOM: کلاس `today--disable-end--holiday` (مثال از کلبه کاربر)
- در API: `date == امروز` — ممکن است `is_unavailable` باشد (روز قبل رزرو شده باشد)

### 3.3 روز خالی (available) — حالت عادی
```json
{"date": "2026-08-07", "price": 2750000, "is_instant": true}
```
- `is_unavailable` **وجود ندارد یا false**
- قیمت دارد، قابل رزرو است

### 3.4 روز پر / رزرو شده / بسته (unavailable)
```json
{"date": "2026-08-01", "price": 1300000, "is_unavailable": true}
```
- `is_unavailable: true` ← **این همان حالت «پر» است**
- **قیمت همچنان موجود است!** (قیمت تنظیمشده را نشان میدهد)
- نمیتوان رزرو کرد (در DOM: کلیک کار نمیکند)

### 3.5 روز نیمهپر (روز چرخش / Turnover Day) — ✅ تأییدشده توسط کاربر
**تعریف (از کاربر):** وقتی شب قبل **پر** بوده و این روز **خالی** است → این روز «نیمهپر» است.
- مسافر قبلی باید تا **۱۲ ظهر** خارج شود (checkout)
- مسافر جدید از **۲ بعدازظهر (۱۴:۰۰)** وارد میشود (check-in)
- یعنی روز بین دو رزرو — عملاً نیمی از روز اشغال است

**تشخیص در API:** `is_unavailable` شب قبل = true و `is_unavailable` امروز = false
```
prev.is_unavailable == true  و  cur.is_unavailable == false  →  امروز نیمهپر است
```

**نمونه واقعی (room 3245625 — پرترین اتاق):**
```
رزرو: 2026-08-01 (پنجشنبه) + 2026-08-02 (جمعه) ← پر
روز چرخش/نیمهپر: 2026-08-03 ← خالی (قیمت 2,000,000)
مسافر قبلی تا ۱۲ ظهر 2026-08-03 خارج، مسافر جدید ۱۴:۰۰ وارد
```

**آمار واقعی — شاخص نیمهپر (تعداد روزهای چرخش):**
| اتاق | روزهای پر | روزهای نیمهپر (چرخش) |
|---|---|---|
| 3245625 | ۳۷ | ۶ |
| 3186964 | ۱۵ | ۳ |
| 3178842 | ۱۲ | ۴ |
| 3297585 (کلبه کاربر) | ۱ | ۱ |
| 3149749 | ۰ | ۰ |

**کاربرد این مفهوم:**
- روز نیمهپر = روزی که میزبان باید **نظافت** انجام دهد (بین دو رزرو)
- در تقویم میزبان، این روزها قابل رزرو با **ورود عصرگاهی** هستند
- برای تحلیل رقبا: اتاقی که روزهای چرخش زیادی دارد = رزروهای پشتسرهم دارد = پرتقاضاتر است
- ⚠️ در API، روز نیمهپر ظاهراً همان available معمولی است (فقط از روی همسایه قبلی قابل تشخیص است)

### 3.6 روز تعطیل (holiday)
```json
{"date": "2026-08-04", "price": 3900000, "is_instant": true, "is_holiday": true}
```
- تعطیل رسمی ایران (در تقویم با کلاس `holiday` مشخص میشود)
- معمولاً قیمت بالاتر

### 3.7 روز پیک (peak)
```json
{"date": "2026-08-12", "price": 5000000, "is_holiday": true, "is_peak": true, "is_weekend": true}
```
- شلوغترین روزها (تعطیلات بلند، عیدها)
- بالاترین قیمت

## 4. 📊 الگوهای مشاهدهشده واقعی (بررسی ۳۴ اتاق بابلکنار)

### توزیع «روزهای پر» در بین کلبهها:

| درصد پر | تعداد اتاق | مثال |
|---|---|---|
| 0–1% | ۴ اتاق | 3149749 (خالی!) |
| 3–5% | ۶ اتاق | 3204775, 3176580 |
| 7–13% | ۷ اتاق | 3186964, 3178842 |
| **32%** | ۱ اتاق | **3245625** (پرترین!) |

### اتاق پرترین (3245625 — 32%):
- ۳۷ روز از ۱۱۵ روز آینده = **unavailable**
- یک بلوک ۳۱ روزه از 23-08 تا 22-09 = **رزرو طولانی/بسته برای یک ماه** (احتمالاً رزرو کامل یا بستن موقت)
- + ۶ بلوک کوچک (۱–۲ شب) = رزروهای کوتاه آخر هفته
- الگو: **بیشتر روزهای پر = پنجشنبه/جمعه + تعطیلات**

### اتاق خالی (3149749 — 0%):
- هیچ روزی unavailable نیست
- کل ۱۱۵ روز آینده باز است

## 5. 🧠 شاخصهای مفید (مشتق از API)

### 5.1 نرخ اشغال آینده (Occupancy Rate)
```
occupancy = (تعداد nights با is_unavailable) / (کل nights)
```
- **0–5%:** اتاق تقریباً خالی (کمفروش / تازه / قیمت بالا)
- **5–15%:** نرمال (رزروهای آخر هفته)
- **15%+:** پر / پرتقاضا
- **30%+:** فوق العاده پر (یا بسته موقت)

### 5.2 بلوکهای رزرو (Consecutive unavailable)
- گروههای پشتسرهم از `is_unavailable` = رزرو واقعی
- بلوک ۱–۳ شب = رزرو آخر هفته
- بلوک ۷+ شب = رزرو هفتگی/ماهانه (یا بسته)
- **تشخیص:** اگر بلوک طولانی + قیمت بالا → رزرو طولانی؛ اگر بلوک طولانی + قیمت پایین → احتمالاً بسته توسط میزبان

### 5.2b شاخص نیمهپر / چرخش (Turnover Index) — ⭐ جدید
```
نیمهپر = روز خالی که شب قبلش پر بوده است
turnover_count = تعداد روزهایی که prev.is_unavailable == true و cur.is_unavailable == false
```
- **۰ =** اتاق خالی یا رزروهای تکشبه پراکنده (تقاضای کم)
- **۳–۶ =** رزروهای پشتسرهم آخر هفته (تقاضای نرمال)
- **۶+ =** چرخش بالا — اتاق پرطرفدار (تقریباً هر آخر هفته رزرو میشود)
- کاربرد: رتبهبندی تقاضای واقعی رقبا (بهتر از success_books که گاهی بهروز نیست)

### 5.3 درآمد بالقوه (Revenue Estimate)
```
درآمد = Σ (price × 30% × روزهای available)
```
- فقط برای مقایسه نسبی (نه عدد دقیق)

### 5.4 دامنه نرخ (Rate Range)
- `min_price` / `max_price` از room API = پایه نرخگذاری
- در تقویم: `min(price)` و `max(price)` در ۱۱۵ روز

### 5.5 «تخفیف امروز/فردا»
- `today_discount` / `tomorrow_discount` در `room` — تخفیف لحظه آخری
- `enable_today_discount` / `enable_tomorrow_discount` — آیا فعال است؟

## 6. 💡 ایدههای کاربردی (برای بعدها)

### 6.1 نقشه حرارتی تقویم (Heatmap)
- برای هر کلبه: تقویم ۳ ماهه با رنگبندی:
  - 🟢 سبز = خالی
  - 🟡 زرد = آخر هفته/تعطیل (قیمت بالاتر)
  - 🔴 قرمز = پر (unavailable)
- یک نگاه = وضعیت کل بازار

### 6.2 شاخص «چقدر پر است» برای هر کلبه
- درصد پر = سیگنال تقاضا
- ستون جدید در داشبورد: 🔴 پر، 🟡 نیمهپر، 🟢 خالی
- **تعریف پیشنهادی:**
  - خالی: 0–5%
  - نیمهپر: 5–15%
  - پر: 15%+

### 6.3 ردیاب رزرو بلندمدت
- اگر اتاقی بلوک ۷+ شب unavailable شد → تغییر مهم (رزرو طولانی/بسته)
- Cron روزانه: diff تقویم قبلی و جدید
- «اتاق X این هفته ۱۰ روز بسته شد» → یعنی رزرو شده یا میزبان بسته

### 6.4 هشدار «اولین شب آزاد»
- برای کلبههای پر: پیدا کردن نزدیکترین شب available
- «کلبه X تا ۱۲ شهریور پر است، اولین شب آزاد: ۱۳ شهریور»

### 6.5 تحلیل قیمت پویا
- مقایسه price روزهای عادی vs آخر هفته vs تعطیل vs پیک
- کلبههای با «قیمت ثابت» vs «قیمت پویا»
- الگوی قیمتگذاری رقبا

### 6.6 محاسبه درآمد تخمینی رقبا
- Σ(price × days) برای کل بازه = درآمد بالقوه
- مقایسه: «کلبه X در ۳ ماه آینده ۸۰ میلیون تومان پتانسیل دارد»

### 6.7 پیشبینی تقاضا (بعد از ۳۰ روز داده)
- روند: چند روز پر در هفتههای مختلف
- «هفته ۱۵ شهریور ۴۰٪ پر است» → قیمتگذاری هوشمند

## 7. ⚠️ محدودیتها و نکات

1. **API از دیروز شروع میشود (~۸۵–۱۱۵ شب: دیروز + امروز + ۳–۴ ماه آینده)** — فقط یک روز گذشته برمیگردد؛ بقیه تاریخهای گذشته را باید خودت محاسبه کنی. ⚠️ دیروز ممکن است `is_unavailable: true` باشد ولی گذشته است نه پر
2. **`is_unavailable` بین «رزرو شده» و «بسته توسط میزبان» تفاوت قائل نیست** — فقط با الگوی قیمت/بلوک میتوان حدس زد
3. **اتاقهای چندواحدی (`units_count > 1`)**: رفتار نامشخص است — احتمالاً همان available/unavailable
4. **بدون پارامتر تاریخ** — همیشه کل بازه میآید (برای cron عالی است، برای query سنگین)
5. **نرخ اشغال آینده ≠ نرخ اشغال واقعی گذشته** — فقط دید رو به جلو است
6. برای رزروهای واقعی (past) به API دیگری نیاز است (مشخص نشده)

## 8. خلاصه

| مفهوم | فیلد API | کلاس DOM |
|---|---|---|
| **گذشته** | `date < today` (فقط دیروز میآید، ⚠️ به is_unavailable نگاه نکن) | `beforeToday` (disabled) |
| امروز | `date == today` | `today--disable-end` |
| خالی | بدون `is_unavailable` و `date >= today` | قابل کلیک |
| **پر** | `is_unavailable: true` و `date >= today` | غیرفعال |
| تعطیل | `is_holiday: true` | کلاس `holiday` |
| پیک | `is_peak: true` | — |
| آخر هفته | `is_weekend: true` | — |

**API تقویم = `api.jajiga.com/api/nights?room_id={id}` — رایگان، بدون auth، ~۸۵–۱۱۵ شب.**
